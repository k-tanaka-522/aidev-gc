# さくら市 GC移行案件 — E2Eテストシナリオ

## 案件概要（架空設定）

- **顧客:** さくら市（人口12万人、関東圏の地方自治体）
- **対象システム:** マイナンバーカード関連サービス（住民向けWebポータル + 庁内業務システム）
- **現行環境:** Heroku上で稼働中（PostgreSQL、Node.js、Redis）
- **移行先:** ガバメントクラウド（AWS ap-northeast-1）
- **GC利用方式:** 共同利用（県のGC共同利用グループに参加）
- **移行方式:** リフト＆シフト（R1）→ 一部モダナイズ（R2: コンテナ化検討）
- **セキュリティレベル:** 高（マイナンバー関連、ISMAP対応必須）
- **LGWAN接続:** あり（庁内業務システム用）
- **ASP連携:** 2社（住基ネット連携、コンビニ交付連携）
- **RTO/RPO:** 住民向け 4時間/1時間、庁内 8時間/4時間
- **予算感:** 初期構築 3,000万〜5,000万円（概算）
- **期間:** 12ヶ月（2026年4月〜2027年3月本稼働予定）

## 現行システム構成（Heroku）

### アプリケーション構成
- **Web App:** Node.js (Express) × 3 dyno (Standard-2X)
- **Worker:** Node.js × 1 dyno（非同期処理、バッチ）
- **DB:** Heroku Postgres Standard-4（100GB、接続数500）
- **Cache:** Heroku Redis Premium-3
- **Storage:** AWS S3（既にAWSを一部利用、住民提出書類PDF保存）
- **CDN:** Cloudflare（住民向けポータル）
- **認証:** マイナンバーカード電子証明書（JPKI）+ ID/PW

### 外部連携
- 住基ネット接続（LGWAN経由、SOAP API）
- コンビニ交付連携（専用VPN、REST API）
- マイナポータル連携（インターネット経由、API）

### 現行の課題
- Herokuの料金体系変更で運用コスト増大
- GC利用が義務化されつつある
- ISMAP未対応（Heroku）
- スケーラビリティの限界（住民向けピーク時にレスポンス劣化）
- LGWAN接続が間接的（VPN経由で遅延あり）
