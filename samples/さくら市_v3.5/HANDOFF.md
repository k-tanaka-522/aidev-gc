## 2. さくら市 案件概要

- **顧客:** さくら市（人口12万人、関東圏）
- **対象:** マイナンバーカード関連サービス
- **現行:** Heroku（Node.js × 3 dyno、PostgreSQL、Redis、S3、Cloudflare）
- **移行先:** GC AWS (ap-northeast-1)
- **GC方式:** 共同利用（県グループ）
- **セキュリティ:** ISMAP対応必須
- **LGWAN:** あり（DirectConnect + VPNバックアップ）
- **ASP連携:** 住基ネット、コンビニ交付
- **RTO/RPO:** 住民向け 4h/1h、庁内 8h/4h
- **予算:** 3,000〜5,000万円
- **期間:** 12ヶ月

## 3. テスト実行計画

### 推奨実行順序
```
Phase 0 → Phase 1 → Phase 2 → Phase 3 → Phase 4(並行) → Phase 5 → Phase 6 → Phase 7 → 横断チェック
```

### 各フェーズの実行方法

#### Phase 0: 案件立ち上げ
```
指示: 「さくら市のGC移行案件を立ち上げて。RFPは samples/さくら市/010_RFP/ にある」
期待: tailoring エージェントが起動、案件プロファイル + 有効エージェント判定 + WBS
```

#### Phase 1: 提案見積
```
指示: 「さくら市のRFPをもとに概算見積と技術提案書を作成して」
期待: infra-estimation → infra-proposal の順で起動
出力: outputs/01_提案見積/01-1_見積書/ + 01-2_提案書/
```

#### Phase 2: 要件定義
```
指示: 「さくら市の要件定義を開始して。RFPとPhase 0の結果をもとに」
期待: infra-requirements がパターンA（フル要件定義）モードで起動
出力: outputs/02_要件定義/
```

#### Phase 4: 設計（並行実行）
```
指示: 「さくら市の設計フェーズに入って。要件定義書をもとに全設計書を作成して」
期待: 設計系7エージェントが並行起動（Agent Teams）
出力: outputs/04_設計/04-1_〜04-7_
```

#### Phase 5-7: テスト〜運用
```
指示: 各フェーズの指示をオーケストレーターに投げる
```

## 4. 既知の注意点

1. **コンテキスト長** — 全フェーズ一気にやるとコンテキストが溢れる。フェーズごとにセッションを分けるのが現実的
