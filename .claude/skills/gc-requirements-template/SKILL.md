### 2.4 機能要件テンプレート（詳細例）

```
【REQ-F-001: ユーザ登録】

1. 概要
  国民がメールアドレスとパスワードで新規ユーザ登録できる

2. 入出力
  入力: メールアドレス、パスワード、氏名、住所
  出力: ユーザID、登録確認メール

3. 前提条件
  - メールアドレスが有効か （RFC5321形式）
  - パスワードが強力か （8文字以上、大文字+数字+記号）

4. 処理フロー
  Step 1: ユーザが [新規登録] ボタンをクリック
  Step 2: 登録フォーム表示
  Step 3: ユーザが情報入力＆送信
  Step 4: バリデーション実行
       - エラー時: エラーメッセージ表示（入力値保持）
       - OK時: ステップ5へ
  Step 5: ユーザID生成、DB登録
  Step 6: 確認メール送信
  Step 7: 確認ページ表示（「メールで確認してください」）

5. エラー処理
  - メールアドレス重複: 「既に登録されています」メッセージ
  - パスワード不正: 「8文字以上」メッセージ
  - タイムアウト: セッション再確立

6. 優先度
  Must （本機能がなければシステム起動不可）
```

## 3. 非機能要件

### 3.1 非機能要件一覧

非機能要件の ID 形式: `REQ-N-{カテゴリ}-{番号}`

```
REQ-N-AV-001: 稼働率
  目標値: 99.9% （3ナイン）
  根拠: 行政サービスのため24時間稼働が必須

REQ-N-PERF-001: レスポンス時間
  目標値: p99 < 200ms
  根拠: ユーザ体験向上

REQ-N-SEC-001: 認証方式
  要件: OAuth 2.0 / OIDC 準拠
  根拠: ISMAP 標準

... (6カテゴリ×各5-8項目)
```

### 3.2 非機能要件カテゴリと詳細

詳細は **gc-nonfunctional-checklist** スキルを参照

| カテゴリ | 例 |
|---------|-----|
| 可用性 | RTO/RPO, 稼働率, 冗長化 |
| 性能 | レスポンス時間, スループット |
| セキュリティ | 認証, 暗号化, 監査ログ |
| 運用性 | バックアップ, 監視, パッチ管理 |
| 移行性 | 移行データ量, スケーラビリティ |
| エコロジー | コスト効率, リソース最適化 |

## 4. GC 固有要件

### 4.1 GCAS 申請要件

```
GC利用契約書 (GCAS) に基づく技術要件

□ VPC 分離: シングルテナント用 VPC
□ セキュリティグループ: 最小権限ルール
□ 暗号化: 転送中 (TLS 1.2+), 保存中 (KMS)
□ ロギング: CloudTrail, VPC フローログ有効化
□ IAM: リソースベースポリシー＋ロールベース制御
□ バックアップ: RTO/RPO に応じた自動バックアップ
□ 監査: 定期セキュリティスキャン（Reacher or 同等）
```

### 4.2 ISMAP チェックリスト対応

デジタル庁 ISMAP の以下項目に対応:

- ✓ 認証の強化（MFA 推奨）
- ✓ 転送中データ暗号化（TLS 1.2以上）
- ✓ 保存データ暗号化（KMS）
- ✓ 監査ログ（CloudTrail）
- ✓ アクセス制御（IAM ポリシー）

詳細: `/docs/ismap-checklist.xlsx` 参照

### 4.3 デジタル庁非機能要件標準への準拠

デジタル庁が公開する非機能要件標準 v1.2 に対応

| 標準項目 | 対応状況 |
|---------|---------|
| API設計 | OpenAPI 3.0 |
| ロギング | JSON形式, 標準フィールド |
| 監視 | CloudWatch + カスタムメトリクス |

## 記載ルール

### 要件書作成時のルール

1. **要件 ID の統一**
   - 機能: REQ-F-001, REQ-F-002...
   - 非機能: REQ-N-{カテゴリ}-{番号}
   - GC固有: REQ-GC-001...

2. **定量化**
   - 「早い」→「p99 < 200ms」
   - 「安全」→「TLS 1.2以上」
   - 「多く」→「99.9% 稼働率」

3. **トレーサビリティ**
   - 各要件に設計書・テストケースが対応
   - 要件→設計→テストの一対一対応

4. **優先度の記載**
   - Must: なければシステム不可
   - Should: できれば実装
   - Could: 余裕があれば
   - Won't: 今回は対象外

5. **未決事項の管理**
   - 期限を明記（「後で決める」は禁止）
   - 影響度を評価
   - 責任者を指定
