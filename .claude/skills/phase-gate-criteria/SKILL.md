# フェーズゲート判定基準

## 1. 全体フェーズ構成

```
Phase 0: 案件立ち上げ
  ├─ 案件初期化、テーラリング
  └─ Gate 0: 案件基本情報確定

Phase 1: 企画・要件定義
  ├─ 要件ヒアリング、現行調査
  ├─ ビジネス要件 / 非機能要件定義
  └─ Gate 1: 要件定義書確定

Phase 2: 基本設計
  ├─ ネットワーク / セキュリティ / 監視 / バックアップ設計
  ├─ コスト最適化設計
  └─ Gate 2: 設計書確定（初版）

Phase 3: 詳細設計
  ├─ 各設計を詳細化（IaC 実装対象）
  ├─ 性能チューニング設計、セキュリティ詳細化
  └─ Gate 3: 設計書確定（最終版）

Phase 4: 実装（IaC）
  ├─ Terraform / CloudFormation コード記述
  ├─ IaC レビュー、テスト環境デプロイ
  └─ Gate 4: IaC コード確定

Phase 5: テスト・検証
  ├─ 単体 / 結合 / 性能 / セキュリティテスト
  ├─ DR テスト（リストア / フェイルオーバーテスト）
  ├─ 本番リハーサル（Stage 1-3）
  └─ Gate 5: テスト完了、本番移行準備完了

Phase 6: 本番移行（カットオーバー）
  ├─ Go/No-Go 判定、最終チェック
  ├─ DNS / トラフィック切替
  └─ Gate 6: 本番化完了

Phase 7: 本番安定化（Day +1 〜 +30）
  ├─ 日次監視、パフォーマンス確認
  ├─ バグ修正、最適化
  └─ Gate 7: 本番運用安定判定（Day +7）

Phase 8: 本番運用
  ├─ 通常運用、パッチ管理
  ├─ パフォーマンス最適化、コスト最適化
  └─ Gate 8: 定期レビュー（月次 / 四半期ごと）
```

## 2. 各フェーズゲート判定基準

### Gate 0: 案件立ち上げ

**所要時間**: 1-2 週間

**必須成果物**:
- [ ] 案件基本情報書（案件名、顧客、対象システム、規模）
- [ ] ステークホルダーリスト（役割、連絡先）
- [ ] テーラリング実施結果（有効エージェント、無効エージェント）
- [ ] プロジェクトチャーター（目的、目標、制約）
- [ ] 初期リスク登録簿

**品質基準**:

| 項目 | 基準 | 測定方法 |
|------|------|--------|
| ステークホルダー合意 | 全員署名済み | チャーター確認 |
| テーラリング完全性 | PM 手法 / エージェント構成決定 | テーラリング報告書 |
| 体制確保 | PM、インフラ、テスト、セキュリティ チーム各 1 名以上 | 案件スタッフリスト |

**数値目標**:
- プロジェクト期間: [X ヶ月]
- 予算: [Y 万円]
- リスク件数（初期登録）: ≤ 10 件
- Open Issue: ≤ 5 件

**Pass / Fail 判定**:
- **Pass**: ステークホルダー合意 ≥ 90%, テーラリング完全
- **Fail**: ステークホルダー合意 < 90% / テーラリング未完了

---

### Gate 1: 要件定義完了

**所要時間**: 2-4 週間

**必須成果物**:
- [ ] 要件定義書（ビジネス要件 ≥ 20 件、非機能要件 ≥ 15 項目）
- [ ] 現行システム調査書（AS-IS ドキュメント）
- [ ] ユーザストーリー（≥ 20 件、詳細度含む）
- [ ] 要件トレーサビリティマトリックス（要件 → テストケース）
- [ ] ステークホルダーレビュー完了記録

**品質基準**:

| 項目 | 基準 | 測定方法 |
|------|------|--------|
| 要件の網羅性 | ビジネス要件 ≥ 20 件、非機能要件 ≥ 15 項目 | 要件リストカウント |
| 要件の明確性 | 受け入れ条件（AC）が全要件に記載 | 要件書レビュー |
| トレーサビリティ | 要件 → テストケース対応度 ≥ 95% | TRM 確認 |
| ステークホルダー合意 | 全署名者が承認 | サイン欄確認 |
| ドキュメント品質 | 構成、可読性、一貫性チェック OK | 品質メトリクス |

**数値目標**:
- ビジネス要件数: [X] 件
- 非機能要件数: [Y] 項目
- ユーザストーリー数: [Z] 件（優先度付け完了）
- 現行環境ユーザ数: [N] 名
- 現行データ量: [M] GB
- 現行コスト: [L] 万円/年

**Pass / Fail 判定**:
- **Pass**: 要件数達成 ≥ 90%, AC 記載率 ≥ 95%, ステークホルダー合意取得
- **Fail**: 要件数達成 < 90% / AC 記載率 < 95% / 合意未取得

---

### Gate 2: 基本設計完了（初版）

**所要時間**: 3-5 週間

**必須成果物**:
- [ ] ネットワーク設計書（VPC / Subnet / ルーティング）
- [ ] セキュリティ設計書（IAM / KMS / ネットワークセキュリティ）
- [ ] 監視・ログ設計書（CloudWatch / CloudTrail / VPC Flow Logs）
- [ ] バックアップ・DR 設計書（RPO / RTO 定義）
- [ ] コスト最適化設計書（初期試算）
- [ ] 設計トレーサビリティマトリックス（要件 → 設計）
- [ ] アーキテクチャ図（全体図、ブロック図、データフロー図）

**品質基準**:

| 項目 | 基準 | 測定方法 |
|------|------|--------|
| 設計書ページ数 | ≥ 150 ページ | ページカウント |
| 設計図の完成度 | レジェンド付き、ラベル完備 | 図表レビュー |
| 要件対応度 | 全要件が設計要素に対応 | TRM 確認 |
| セキュリティレビュー | 初版セキュリティレビュー完了 | レビュー記録 |
| AWS 制限値確認 | 制限値超過なし | 技術レビュー |

**数値目標**:
- 設計書総ページ数: ≥ 150 ページ
- ネットワーク設計: VPC × [X] 個, Subnet × [Y] 個
- IAM ロール数: [Z] 個
- セキュリティグループ数: [W] 個
- 月額コスト試算（初期値）: [V] 万円/月

**Pass / Fail 判定**:
- **Pass**: 全設計書完成, 要件対応度 ≥ 95%, セキュリティレビュー OK
- **Fail**: 設計書未完成 / 要件対応度 < 95% / セキュリティ指摘 [高] あり

---

### Gate 3: 詳細設計完了（最終版）

**所要時間**: 2-4 週間

**必須成果物**:
- [ ] 詳細ネットワーク設計書（CIDR、ルート テーブル詳細）
- [ ] 詳細セキュリティ設計書（IAM ポリシー詳細、WAF ルール）
- [ ] 詳細監視設計書（CloudWatch メトリクス詳細、ダッシュボード設計）
- [ ] 性能チューニング設計書（キャッシング戦略、DB パラメータ）
- [ ] 最終コスト見積書（詳細見積、RI / Savings Plans 検討）
- [ ] IaC 実装計画書（terraform module 構成、デプロイ順序）

**品質基準**:

| 項目 | 基準 | 測定方法 |
|------|------|--------|
| 設計の詳細性 | IaC に直結する詳細レベル | 設計 → IaC マッピング確認 |
| リソース命名規則 | 統一、明確（snake_case） | リソースリスト確認 |
| 矛盾検査 | ネットワーク / セキュリティ / 監視間の矛盾なし | 矛盾チェックリスト |
| 関連部署レビュー | セキュリティ / DB / 運用部門承認 | サイン記録 |
| コスト見積精度 | ±10% 以内（標準） | 概算 vs 詳細比較 |

**数値目標**:
- 設計細度: IaC 記述率 ≥ 90%
- リソース総数見積: [X] 個
- 月額コスト見積（詳細値）: [Y] 万円/月（±10%）
- RI 活用率: [Z]%

**Pass / Fail 判定**:
- **Pass**: 設計詳細度 ≥ 95%, 矛盾なし, 全部門承認
- **Fail**: 設計詳細度 < 95% / 矛盾あり / 承認未取得

---

### Gate 4: IaC 実装完了

**所要時間**: 3-6 週間

**必須成果物**:
- [ ] Terraform / CloudFormation コード（全リソース実装）
- [ ] IaC コード レビュー完了記録（≥ 2 人承認）
- [ ] IaC テスト環境デプロイ実行ログ
- [ ] IaC セキュリティスキャン結果（tfsec 等）
- [ ] 環境構築手順書（テスト環境、ステージング環境）
- [ ] リソース一覧（CFn template / terraform state 出力）

**品質基準**:

| 項目 | 基準 | 測定方法 |
|------|------|--------|
| コード品質 | terraform validate エラーなし、linter 警告 ≤ 10 | linter 実行結果 |
| セキュリティ | tfsec 高リスク指摘ゼロ | セキュリティスキャン |
| コードレビュー | 2 人以上承認、LGTM コメント | レビュー記録 |
| テスト環境デプロイ | 成功、リソース確認完了 | デプロイログ |
| タグ / 命名規則 | 100% 統一 | リソースリスト確認 |

**数値目標**:
- IaC ファイル数: [X] ファイル
- IaC 行数: [Y] 行（コメント含む）
- テスト環境デプロイ時間: ≤ 30 分
- コードレビュー指摘数: ≤ 10 件

**Pass / Fail 判定**:
- **Pass**: terraform validate OK, tfsec 高リスク指摘ゼロ, テストデプロイ成功, 2 人承認
- **Fail**: terraform エラーあり / tfsec 高リスク指摘 / デプロイ失敗 / 承認不足

---

### Gate 5: テスト・本番リハーサル完了

**所要時間**: 4-8 週間

**必須成果物**:
- [ ] テスト計画書（全テスト種別含む）
- [ ] テストケース定義書（≥ 50 テストケース）
- [ ] テスト実行ログ（テストケース別実行結果）
- [ ] テスト結果報告書（合否判定、課題記録）
- [ ] 本番リハーサル実行ログ（Stage 1-3）
- [ ] 移行計画書（詳細）
- [ ] Go/No-Go チェックリスト（テンプレート）

**品質基準**:

| 項目 | 基準 | 測定方法 |
|------|------|--------|
| テスト実施率 | ≥ 95% | テストケース数 vs 実施数 |
| テスト合格率 | ≥ 98% | 合格数 / 全テスト数 |
| 性能テスト | SLI 達成率 ≥ SLO 値 | メトリクス測定結果 |
| セキュリティテスト | 高リスク脆弱性ゼロ | セキュリティレポート |
| DR テスト | RTO / RPO 達成確認 | テスト実行ログ |
| 本番リハーサル | Stage 3 実施完了、改善対応完了 | リハーサル実行ログ |

**数値目標**:
- テストケース数: [X] 件（≥ 50）
- 結合テスト実施率: ≥ 95%
- 性能テスト: レスポンスタイム p99 ≤ SLO 値
- リハーサル実施回数: 3 回（各段階 1 回）
- リハーサル所要時間: [Y] 時間

**Pass / Fail 判定**:
- **Pass**: テスト実施率 ≥ 95%, 合格率 ≥ 98%, SLO 達成, リハーサル 3 段階完了
- **Fail**: テスト実施率 < 95% / 合格率 < 98% / SLO 未達成 / リハーサル未完了

---

### Gate 6: 本番移行（カットオーバー完了）

**所要時間**: 1 日（Day 0）

**必須成果物**:
- [ ] Go/No-Go チェックリスト（最終確認、全項目クリア）
- [ ] 移行手順書（最終版、テスト環境で検証済み）
- [ ] 切戻し手順書（テスト済み）
- [ ] カットオーバー実行ログ（タイムスタンプ付き）
- [ ] 本番環境構築完了確認（全リソース稼働確認）
- [ ] トラフィック切替完了記録（DNS / ELB 切替実行）

**品質基準**:

| 項目 | 基準 | 測定方法 |
|------|------|--------|
| Go/No-Go チェック | 100% クリア | チェックリスト確認 |
| 移行実行 | 計画通り実施 | 実行ログ比較 |
| ダウンタイム | 計画値以内 | タイムスタンプ記録 |
| トラフィック流入 | 期待値の ≥ 95% | アクセスログ / メトリクス |
| エラー率 | ≤ 0.1%（初期 1 時間） | CloudWatch メトリクス |

**数値目標**:
- ダウンタイム: ≤ [X] 分（計画値）
- トラフィック復帰時間: ≤ [Y] 分
- エラー率（1 時間後）: ≤ 0.1%
- 本番環境 CPU 使用率: ≤ 70%

**Pass / Fail 判定**:
- **Pass**: Go/No-Go チェック 100%, ダウンタイム ≤ 計画値, トラフィック ≥ 95%
- **Fail**: Go/No-Go チェック < 100% / ダウンタイム > 計画値 / エラー率 > 0.5%

---

### Gate 7: 本番運用安定化判定（Day +7）

**所要時間**: 7 日間（Day +1 ~ Day +7）

**必須成果物**:
- [ ] 日次監視ログ（7 日分）
- [ ] パフォーマンス分析レポート（CPU / メモリ / ネットワーク）
- [ ] エラーログ分析レポート（原因分析、改善アクション）
- [ ] ユーザ反応 / 問い合わせサマリー
- [ ] 本番安定化判定書

**品質基準**:

| 項目 | 基準 | 測定方法 |
|------|------|--------|
| 稼働率 | ≥ 99.5% | CloudWatch ヘルスチェック |
| エラー率（平均） | ≤ 0.1% | CloudWatch メトリクス集計 |
| パフォーマンス | 99% の時間で SLO 達成 | レスポンスタイム測定 |
| ユーザ報告 | 重大問題なし（SEV1 / SEV2 ≤ 1 件） | インシデント管理システム |
| DB 動作 | 接続エラーなし、レスポンス正常 | DB ログ分析 |

**数値目標**:
- 稼働率: [X]%（目標 99.5%）
- 平均エラー率: ≤ 0.1%
- ユーザ満足度: [Y]%（アンケート / NPS）
- SEV1 インシデント数: ≤ 1 件

**Pass / Fail 判定**:
- **Pass**: 稼働率 ≥ 99.5%, エラー率 ≤ 0.1%, SEV1 ≤ 1 件
- **Fail**: 稼働率 < 99.5% / エラー率 > 0.5% / SEV1 > 1 件 / 重大問題発生

---

### Gate 8: 定期レビュー（運用フェーズ）

**所要時間**: 月次 / 四半期ごと（継続的）

**必須成果物**:
- [ ] 月次 SLI / SLO レポート
- [ ] 月次インシデント集計 / 分析
- [ ] 月次コスト レポート
- [ ] パフォーマンス最適化推奨事項
- [ ] セキュリティアップデート確認

**品質基準**:

| 項目 | 基準 | 測定方法 |
|------|------|--------|
| SLO 達成 | 月単位 ≥ 99.5% | 集計データ |
| コスト削減 | 月額 ≤ 見積値 ×1.1（±10%） | AWS 請求書 |
| セキュリティパッチ | 重大度 Critical: 7 日以内適用 | パッチ管理ログ |
| インシデント対応時間 | MTTR ≤ 15 分（SEV1） | インシデント記録 |

**数値目標**:
- SLO 達成率（月）: ≥ 99.5%
- 月額コスト増加率: ≤ 10%
- セキュリティパッチ適用率: 100%（Critical）, ≥ 95%（High）
- MTTR（Mean Time To Recovery）: SEV1 ≤ 15 分, SEV2 ≤ 1 時間

**Pass / Fail 判定**:
- **Pass**: SLO 達成 ≥ 99.5%, コスト ±10% 以内, セキュリティパッチ適用
- **Fail**: SLO < 99.5% / コスト > 20% 超過 / Critical パッチ未適用
