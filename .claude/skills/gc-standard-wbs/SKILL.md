# GC インフラ標準 WBS テンプレート

## 概要
ガバメントクラウドインフラ案件向けの標準 WBS（Work Breakdown Structure）。9フェーズ × 132タスクで構成。移行方式・自治体規模・セキュリティレベルなどのプロファイルに基づいて、タスク・工数をテーラリングする基盤。

---

## WBS 全体構成

| フェーズ | フェーズ名 | タスク数 | 標準工数範囲 | 期間 | 主担当 |
|---------|----------|--------|-----------|------|--------|
| Phase 0 | 案件入口 | 5 | 40-100 | 2-6週間 | PM |
| Phase 1 | 提案見積 | 12 | 60-160 | 2-4週間 | PM, SE |
| Phase 2 | 要件定義 | 18 | 150-350 | 4-12週間 | SE, BA |
| Phase 3 | 詳細見積計画 | 8 | 60-120 | 2-4週間 | PM, SE |
| Phase 4 | 設計 | 35 | 300-1,000 | 6-16週間 | SE, Arch |
| Phase 5 | 構築 | 22 | 200-800 | 6-12週間 | Eng, DevOps |
| Phase 6 | テスト | 18 | 100-400 | 4-12週間 | QA, SE |
| Phase 7 | 導入・移行 | 12 | 80-300 | 3-8週間 | Ops, SE |
| Phase 8 | 運用・保守 | 6 | 60/月 以上 | 継続 | Ops |
| **合計** | - | **136** | **1,050-3,230** | **36-76週間** | - |

## WBS 適用時のテーラリングルール

### ルール1: 移行方式によるタスク削減・追加

```
リフト案件の場合:
- Phase 4 タスク 4.3.1 (新規アーキテクチャ設計) は簡略化 (-20%)
- Phase 5 タスク 5.4 (データ移行) は詳細化 (+30%)

新規構築案件の場合:
- Phase 2 タスク 2.2 (現行調査) は削除 (-40人日)
- Phase 4 タスク全て +50%
```

### ルール2: セキュリティレベルによるテスト工数調整

```
セキュリティレベル = 「中」 の場合:
- Phase 6 タスク 6.4 (セキュリティテスト): 標準 (80人日)

セキュリティレベル = 「高」 の場合:
- Phase 6 タスク 6.4: ×1.5 = 120人日 (脆弱性診断追加)

セキュリティレベル = 「最高」 の場合:
- Phase 6 タスク 6.4: ×2.0 = 160人日 (侵入テスト追加)
```

### ルール3: 自治体規模による調整工数

```
中規模以上の自治体の場合:
- Phase 0 タスク 0.1.2 (ステアリング): 有効化 (+8人日)
- Phase 1 以降、月1回のステアリング報告 +6人日/月
```
