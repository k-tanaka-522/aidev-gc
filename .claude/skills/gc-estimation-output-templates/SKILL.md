# GC 見積・提案書 出力テンプレート集

## テンプレートA: 社内稟議用見積（概算）

```
【形式】 A4 1-2頁、Excel / PDF

【対象】 営業初期、社内承認ステップ、価格提案前

【含める項目】
- 案件名、対象自治体、見積日
- フェーズ別工数表（Phase 0-3）
- 見積総額、人日単価
- 工数内訳（ボトムアップで根拠記載）
- リスク・前提条件

【記載例】

┌─────────────────────────────────────────────────────┐
│ 概算見積（社内稟議用）                              │
├─────────────────────────────────────────────────────┤
│ 案件名: A市 基幹システムGC移行                       │
│ 見積日: 20XX年Y月Z日                                │
├─────────────────────────────────────────────────────┤
│ フェーズ別工数                                      │
│ Phase 0: 60人日 （GCAS申請）                         │
│ Phase 1: 80人日 （RFP分析・見積）                    │
│ Phase 2: 200人日 （要件定義）                        │
│ Phase 3: 80人日 （詳細見積計画）                     │
│ ─────────────────                                   │
│ 合計: 420人日                                       │
├─────────────────────────────────────────────────────┤
│ 見積額: 420人日 × 80万円 = 3,360万円（税抜）       │
│        + 消費税 336万円                             │
│      = 3,696万円（税込）                            │
├─────────────────────────────────────────────────────┤
│ リスク: ユーザー協力遅延 → Phase 2 +2週間           │
│ 前提: 既存ドキュメント完備、ヒアリング協力          │
└─────────────────────────────────────────────────────┘
```

## テンプレートC: 技術提案書（営業資料）

```
【形式】 A4（カラー）、PowerPoint / PDF、10-20頁

【対象】 営業ステップ、ビジネス交渉、技術信頼度向上

【含める項目】
1. 表紙・企業紹介
2. 案件理解・現状分析
3. 提案技術方針（ネットワーク、セキュリティ、アーキテクチャ）
4. 実装体制・メンバー紹介
5. スケジュール・フェーズ分割
6. 見積サマリ（詳細WBS）
7. リスク・対応方針
8. 参考実績・事例

【記載例】

【P1】表紙
┌─────────────────────────────────────┐
│     [企業ロゴ]                       │
│                                   │
│                                   │
│   技術提案書                        │
│                                   │
│   A市 基幹システムGC移行             │
│   プロジェクト                      │
│                                   │
│                                   │
│   提案企業: [企業名]                 │
│   提案日: 2024年4月6日               │
└─────────────────────────────────────┘

【P2】案件理解
- 現状: オンプレミス（COBOL+Oracle）の基幹システム
- 課題: 老朽化、保守難、セキュリティリスク
- 目標: GCへの移行、クラウドネイティブ化
- 移行方式: R1（IaaS+RDS活用）

【P3】技術方針
- GC（AWS）を採用、LGWAN接続
- IaC（Terraform）による自動化
- ISMAP対応によるセキュリティ強化
- マルチAZによる99.99%可用性

【P4】ネットワーク設計図
[VPC・ネットワークトポロジー図、LGWAN接続、DirectConnectなど]

【P5】セキュリティ設計図
[IAM構成、KMS暗号化、CloudTrail、ログ監視など]

【P6】実装体制
[テーブル: PM, Architect, SE(複数), NW-SE, Sec-SE, DB-SE, QA, etc.]

【P7】スケジュール（Gantt）
[Phase別のマイルストーン、並行運用、本稼働日など]

【P8】見積サマリ
[フェーズ別工数、人数、期間、見積額]

【P9-10】詳細WBS（Phase4設計を例）
[タスク一覧、工数、期間、依存関係]

【P11】リスク・対策
[表: リスク項目、影響度、対策内容]

【P12】参考実績
[過去のGC案件、同規模案件、セキュリティ対応実績など]

【P13】企業紹介
[企業概要、アワード、認定資格（ISMAP、ISO27001など）]
```
