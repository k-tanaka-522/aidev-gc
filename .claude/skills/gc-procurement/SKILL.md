# GC 調達仕様書ポイント 実装ガイド

## 概要
ガバメントクラウド（GC）を調達・導入する際に、自治体側が RFP（Request for Proposal）に記載すべき要件、および提案企業が対応すべき GC 特有の調達要件をまとめたガイド。

---

## GC 調達仕様書 の主要要素

### 1. GCAS (ガバメントクラウド・アカウント・サービス) 要件

#### 1.1 GCAS 申請主体の決定
**自治体が決定すべき事項:**

```
□ 申請主体:
   □ 自治体（単独利用の場合）
   □ GC運用側（共同利用の場合）

□ CEP (契約企業プロフィール) 登録:
   □ 提案企業は既に登録済みか
   □ 新規登録が必要か
   □ パートナー企業（ASP）のCEP確認

□ GCAS 承認期間:
   □ 通常 2-4週間を要するため、スケジュールに組み込む
   □ GCからの質問対応体制を用意
```

#### 1.2 CEP (契約企業プロフィール) 要件

**提案企業が準備すべき提出書類:**

| 書類 | 内容 | 提出時期 |
|------|------|---------|
| **企業概要書** | 企業名、代表者、所在地、連絡先 | Phase 1 |
| **セキュリティチェックシート** | 情報セキュリティ体制、認定資格、監査履歴 | Phase 1 |
| **誓約書** | GC調達仕様への準拠を誓約 | 契約時 |
| **実績書** | 過去のGC案件実績、同規模案件 | Phase 1 |
| **体制書** | PM、SE、セキュリティエンジニア等の体制 | Phase 2 |

**セキュリティチェックシート の主要項目:**

```
□ 情報セキュリティマネジメント体制
   □ セキュリティ責任者の配置
   □ セキュリティポリシーの有無
   □ セキュリティ教育の実施状況

□ 認定資格・監査履歴
   □ ISO 27001 認定（必須）
   □ ISMAP 認定実績
   □ 第三者監査履歴（会計監査、セキュリティ監査）

□ 情報セキュリティ事故対応
   □ 過去3年の情報セキュリティ事故有無
   □ 事故対応手順書の有無

□ 下請け管理
   □ 下請け企業（パートナー、ASP）のセキュリティ確認方法
   □ 下請け企業のCEP登録状況確認
```

### 2. ISMAP (情報セキュリティマネジメント適格性認定) 対応要件

#### 2.1 ISMAP 要件の選別

**自治体が決定:**

```
□ ISMAP 対応レベル:
   □ ISMAP認定済みクラウドの利用（現状、AWS/Azure/Google Cloud GC）
   □ ISMAPの準拠基準への対応（セキュリティ要件の詳細化）
   □ ISMAPの定期監査対応（年1回以上）

□ 対応範囲:
   □ インフラ全体
   □ 個人情報を扱うシステムのみ
   □ その他（明記）
```

#### 2.2 提案企業が対応すべき ISMAP 要件

| 要件項目 | 対応内容 | 実装フェーズ |
|---------|--------|----------|
| **アクセス制御** | IAM ロール、MFA、IP制限 | Phase 4 設計 |
| **暗号化** | AES-256（保存時）、TLS 1.2（転送時） | Phase 4 設計 |
| **監査ログ** | CloudTrail、VPC Flow Logs、ALB ログ | Phase 5 構築 |
| **脆弱性診断** | 脆弱性診断ツール（自動+手動）による診断 | Phase 6 テスト |
| **セキュリティテスト** | ペネトレーションテスト実施可能性 | Phase 6 テスト |
| **運用ポリシー** | セキュリティ監視、ログ管理、インシデント対応 | Phase 8 運用 |

#### 2.3 ISMAP 監査対応のための体制

```
【提案企業が準備すべき項目】

□ セキュリティ責任者:
   □ ISMAP 監査対応の窓口
   □ セキュリティ方針の策定・実行

□ 監査証跡の保管:
   □ CloudTrail ログ: 最低1年間保持
   □ 脆弱性診断報告書: 各回の完全保管
   □ セキュリティインシデント対応記録: 全て記録

□ 定期的な監視・評価:
   □ 月次セキュリティレビュー（ログ分析）
   □ 四半期ごとの脆弱性診断
   □ 年1回のセキュリティ監査（外部監査機関）

□ 改善プロセス:
   □ 指摘事項への対応計画策定
   □ 対応実施とフォローアップ
```

### 3. ASP (アプリケーション・サービス・プロバイダ) 要件

#### 3.1 ASP の定義と管理

**GC 上で動作する外部システム:**

```
【ASP の例】
- 人事給与システム（XXXXX）
- 福祉業務システム（YYYYY）
- 会計業務システム（ZZZZZ）
```

#### 3.2 ASP 要件の記載項目

**RFP に記載すべき事項:**

| 項目 | 記載内容 |
|------|--------|
| **ASP 一覧** | システム名、ベンダー、現在の稼働状況 |
| **IF 要件** | GC 上のシステムと ASP 間のデータ授受方法 |
| **セキュリティ** | ASP が個人情報を扱うか、暗号化対応 |
| **CEP 確認** | 各 ASP ベンダーの CEP 登録状況 |
| **運用体制** | ASP ベンダーとの連携体制、問い合わせ窓口 |

#### 3.3 ASP 連携時の提案企業の責務

```
【提案企業が実施すべき項目】

□ IF要件の詳細化:
   □ 各ASPとのデータ連携仕様書作成
   □ データフォーマット、スケジュール定義

□ セキュリティ確認:
   □ 各ASPベンダーのCEP登録確認
   □ 個人情報の取扱い方針確認
   □ 暗号化対応状況確認

□ 連携テスト:
   □ 各ASP との結合テスト計画策定
   □ テスト実施、問題対応

□ 運用体制:
   □ ASPとの連携窓口設定
   □ 問題発生時の連絡体制
```

#### 3.4 複数 ASP 管理のポイント

```
【複数ASP（3個以上）の場合】

□ 優先度管理:
   □ 各ASPの重要度を評価
   □ 本稼働スケジュールを段階的に決定
   □ 重要度の高い順に移行

□ IF 統合テスト:
   □ 全ASPを含めた統合テスト環境構築
   □ データ同期の完全性確認

□ 運用手順:
   □ 各ASPの問い合わせ窓口・フローを明確化
   □ インシデント時の責任範囲を明記
```

### 4. 運用管理補助者 要件

#### 4.1 運用管理補助者 の定義

```
GC上で稼働するシステムの日常的な監視、運用業務を支援する人員。
自治体内製の運用チームの不足分を補う、あるいは専門性を補完する役割。
```

#### 4.2 運用管理補助者 の配置基準

**自治体が決定すべき事項:**

| 規模 | 必要人数 | 形態 |
|------|--------|------|
| **小規模自治体** | 0.5-1 名 | 兼任、派遣 |
| **中規模自治体** | 1-2 名 | 専任 or 派遣 |
| **大規模自治体** | 2-3 名 | 専任チーム |

**勤務形態の選択:**

```
□ 派遣形式:
   □ 提案企業から運用管理補助者を派遣
   □ 自治体の運用チームに統合
   □ 期間: 初期運用3ヶ月～1年

□ 委託形式:
   □ 提案企業が運用業務の一部を委託受託
   □ 自治体の施設に常駐しない
   □ リモート対応 + 定期巡回

□ 協力形式:
   □ 技術支援（オンコール）のみ
   □ 日常的な常駐は不要
   □ 問題発生時に専門家派遣
```

#### 4.3 運用管理補助者 の責務

```
【日常監視業務】
- CloudWatch ダッシュボードの監視
- アラート受信・初期対応
- ログ確認・異常検知
- 簡単なトラブルシューティング

【定期保守業務】
- パッチ適用のスケジューリング・実行
- バックアップ・リストア確認
- DR テストの準備・実行支援
- セキュリティアップデート対応

【ドキュメント作成・運用】
- Runbook（運用手順書）の作成・更新
- インシデント報告書の作成
- 月次・四半期レポート作成

【ユーザー支援】
- 自治体職員のクラウド操作研修
- FAQ 対応
- 問題報告の受付・分類
```

#### 4.4 運用管理補助者 の配置スケジュール

```
【Phase 5-8 での配置計画】

Phase 5（構築）:
- 0.5-1 名の補助者が構築確認に参画
- 運用手順書の下見作成開始

Phase 6（テスト）:
- 補助者が運用テストシナリオ作成に参画
- 本番同等環境での監視・対応訓練

Phase 7（導入・移行）:
- 1-2 名の補助者を常駐配置
- 本稼働後24時間体制で対応

Phase 8（本運用）:
- 初期3ヶ月: 専任配置（段階的削減）
- 3ヶ月後: 派遣 or 協力形式へ移行

【運用管理補助者スキル要件】
□ Linux/Windows システム管理経験（3年以上）
□ クラウド（AWS）基本知識
□ セキュリティ基礎知識
□ ネットワーク基本知識
□ コミュニケーション能力（自治体職員との調整）
```

### 5. 自治体ネットワーク接続要件

#### 5.1 LGWAN 接続の確認

```
【RFP に記載すべき事項】

□ 現在のLGWAN接続状況:
   □ 既に接続しているか、新規接続か
   □ 既に接続している場合、接続仕様（速度、ルータ）

□ 接続先:
   □ LGWAN ネットワーク側のゲートウェイ仕様
   □ 既存のゲートウェイを流用するか、新規調達か

□ 接続方式:
   □ VPN（暗号化）を利用するか
   □ DirectConnect（専線）を利用するか
```

#### 5.2 提案企業の責務

```
【ネットワーク接続設計】
- 既存LGWAN ゲートウェイとの互換性確認
- GC側VPC での LGWAN 専用ネットワーク設計
- ルーティング、ファイアウォール設定

【接続テスト】
- LGWAN経由でのアクセス確認
- 通信速度・レイテンシ測定
- セキュリティ要件（暗号化、VPN）の確認

【トラブルシューティング】
- LGWAN側ゲートウェイベンダーとの調整
- 接続問題時の原因特定・対応
```

### 6. セキュリティ・監査対応要件

#### 6.1 監査証跡（Audit Trail）の保管要件

```
【RFP に記載すべき要件】

□ ログ保持期間:
   □ 最低1年間（推奨）
   □ 個人情報を扱う場合は最大3年

□ ログの種類:
   □ CloudTrail（全APIコール）
   □ VPC Flow Logs（ネットワークトラフィック）
   □ ALB / NLB アクセスログ
   □ RDS / DB ログ
   □ アプリケーションログ

□ ログの検索・取得:
   □ 監査対応時に迅速に抽出可能
   □ 改ざん防止機能
   □ タイムスタンプの厳密管理
```

#### 6.2 外部監査対応

```
【提案企業の責務】

□ セキュリティ監査への協力:
   □ ログデータの提供
   □ システム構成図・設計書の提出
   □ セキュリティポリシー・手順書の提示

□ 脆弱性診断への対応:
   □ 外部診断機関による診断の実施場所提供
   □ テスト環境の提供
   □ 指摘事項への対応

□ 定期的なセキュリティレビュー:
   □ 自治体側と月1回のセキュリティ確認会議
   □ 新しい脅威への対応状況報告
```

### 7. 調達仕様書に記載すべき免責・特記事項

```
【RFP の免責・特記欄に記載すべき事項】

□ 費用分担:
   □ AWS 利用料は自治体負担（提案企業は見積のみ）
   □ セキュリティ診断費用: 誰が負担するか
   □ ユーザー教育費用: 誰が負担するか

□ スケジュールリスク:
   □ GCAS 承認遅延による期間延長
   □ 自治体側リソース不足による遅延
   □ 予備期間（XX週間）を確保

□ 契約変更:
   □ スコープ変更時は別途見積実施
   □ 追加要件は変更管理プロセスに従う

□ 支払条件:
   □ 人日単価、外部コスト、消費税
   □ 支払スケジュール（契約時/Phase X 完了時など）
   □ 遅延利息等の条件
```

## GC 調達仕様書 チェックリスト

```
【RFP 作成時のチェック】

□ GCAS 関連:
  □ 申請主体（自治体 vs GC運用側）を明記したか
  □ CEP 登録済みベンダーの確認を促したか
  □ GCAS 承認期間（2-4週間）をスケジュールに組んだか

□ ISMAP 関連:
  □ ISMAP 対応レベル（認定クラウド利用 vs 準拠基準）を決定したか
  □ セキュリティ要件の詳細（暗号化、ログ保持）を記載したか
  □ 監査対応の責務分担を明記したか

□ ASP 関連:
  □ 既存 ASP の一覧を記載したか
  □ 各 ASP ベンダーの CEP 登録状況を確認する旨を記載したか
  □ IF 要件の詳細化タイミングを明記したか

□ 運用関連:
  □ 運用管理補助者の配置要件を明記したか（常駐期間、人数）
  □ スキル要件（Linux/Windows/AWS知識）を記載したか
  □ 月次 / 四半期レポートの提出義務を明記したか

□ セキュリティ関連:
  □ ログ保持期間を明記したか（最低1年）
  □ 外部監査対応の責務を記載したか
  □ 脆弱性診断（年2回以上）の実施義務を明記したか

□ ネットワーク関連:
  □ LGWAN 接続仕様を記載したか
  □ DirectConnect（専線）の必要性を明記したか
  □ 既存ゲートウェイとの互換性確認項目を記載したか

□ 支払・契約関連:
  □ 人日単価、外部コスト、消費税を明記したか
  □ 支払スケジュール（契約時/Phase X 完了時）を明記したか
  □ スコープ外項目（AWS利用料、ユーザー教育など）を明記したか
```
