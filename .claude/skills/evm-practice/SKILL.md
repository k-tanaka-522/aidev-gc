# EVM（Earned Value Management）実践ガイド

## 概要

EVM はプロジェクトの進捗とコストを統合的に管理する手法です。3つの基本値（PV, EV, AC）から、複数の指標を計算して健全性を判定します。

---

## 1. EVM の基本概念

### 三つの基本値

#### PV（計画価値：Planned Value）
```
定義: 当日までに計画されていた累積工数またはコスト
計算方法: 各タスクの計画工数を、計画完了日までの累計

例：
Week 1: 40h 計画 → PV = 40h
Week 2: 40h 計画 → PV = 80h
Week 3: 40h 計画 → PV = 120h
（当日が Week 2.5 の場合）PV = 80h + (40h × 0.5) = 100h
```

#### EV（獲得価値：Earned Value）
```
定義: 当日までに実際に完了した累積工数またはコスト
計算方法: 完了したタスクの計画工数の合計（実績ではなく計画値！）

重要: EV は実績工数ではなく、完了タスクの計画工数である

例：
完了したタスク:
- Task A (計画 40h) ✓ 完了
- Task B (計画 30h) ✓ 完了
- Task C (計画 50h) ✗ 未完了

EV = 40h + 30h = 70h
（Task A に実際 45h かかった場合も EV = 40h）
```

#### AC（実績コスト：Actual Cost）
```
定義: 当日までに実際に支出したコスト
構成要素:
- 人件費 (実績工数 × 給与)
- 外注費
- ツール/ライセンス費
- その他支出

例：
- 人件費: 実績工数 150h × ¥8,000/h = ¥1,200,000
- 外注費: ¥300,000
- ツール費: ¥100,000
- AC = ¥1,600,000
```

## 2. EVM 計算式

### SPI（スケジュール効率性指数：Schedule Performance Index）

```
SPI = EV / PV

解釈:
- SPI = 1.0 : 計画通り（進度100%）
- SPI > 1.0 : 進度超過（計画より早い）
- SPI < 1.0 : 遅延（計画より遅い）

警告レベル:
┌──────────────┬────────────────┬──────────┐
│ SPI範囲       │ 評価           │ 対応     │
├──────────────┼────────────────┼──────────┤
│ >= 1.0       │ ✓ 正常          │ 継続     │
│ 0.95-1.0     │ △ 境界          │ 注視     │
│ 0.9-0.95     │ △ 注意          │ 対応計画 │
│ < 0.9        │ ✗ 警告          │ 即対応   │
│ < 0.8        │ ✗ 危機          │ 承認者報告 │
└──────────────┴────────────────┴──────────┘
```

### CPI（コスト効率性指数：Cost Performance Index）

```
CPI = EV / AC

解釈:
- CPI = 1.0 : 予算通り
- CPI > 1.0 : 予算以下（コスト削減）
- CPI < 1.0 : 予算超過

警告レベル:
┌──────────────┬────────────────┬──────────┐
│ CPI範囲       │ 評価           │ 対応     │
├──────────────┼────────────────┼──────────┤
│ >= 1.0       │ ✓ 正常          │ 継続     │
│ 0.98-1.0     │ △ 境界          │ 注視     │
│ 0.95-0.98    │ △ 注意          │ 対応計画 │
│ < 0.95       │ ✗ 警告          │ 即対応   │
│ < 0.85       │ ✗ 危機          │ 承認者報告 │
└──────────────┴────────────────┴──────────┘
```

### EAC（完了時総見積コスト：Estimate At Completion）

**公式1：現在の効率が続く場合**
```
EAC = AC + (BAC - EV) / CPI

例：
AC = ¥5,000,000
BAC = 1,000h → 当初予算 ¥8,000,000
EV = 400h （¥3,200,000相当）
CPI = 3,200,000 / 5,000,000 = 0.64

EAC = 5,000,000 + (8,000,000 - 3,200,000) / 0.64
    = 5,000,000 + 7,500,000
    = ¥12,500,000 (超過 ¥4,500,000!)

→ 報告：「現状の効率が続くと、最終コストは当初計画から +56% となる見通し」
```

**公式2：残り工数は計画通り（改善を見込む）**
```
EAC = AC + (BAC - EV)

この場合、改善策を実行することを前提とする
```

### ETC（完了までの推定残工数：Estimate To Complete）

```
ETC = EAC - AC

例（公式1の場合）:
ETC = 12,500,000 - 5,000,000 = ¥7,500,000
（当初計画の残予算 ¥3,000,000 に対して +150%）
```

### TCPI（完了時必要効率性：To Complete Performance Index）

```
TCPI = (BAC - EV) / (BAC - AC)

解釈: 残りの工程でこの CPI を達成すれば予算内に完了する

例：
BAC = 1,000h
EV = 400h
AC = ¥5,000,000
BAC額 = ¥8,000,000

TCPI = (8,000,000 - 3,200,000) / (8,000,000 - 5,000,000)
     = 4,800,000 / 3,000,000
     = 1.6

→ 解釈：「残りの工程で現在の CPI 0.64 ではなく、
         CPI 1.6 （1.6倍の効率）を達成する必要がある = ほぼ不可能」
```

### 完了予定日の予測

```
予測完了日 = 当日 + (残余 PV) / 平均 SPI

例：
当日: 2026-04-15
総 PV: 1,000h
現在の PV: 600h
平均 SPI: 0.85

残余 PV = 1,000h - 600h = 400h
予測完了日 = 2026-04-15 + (400h / 0.85) / 8h/day
           = 2026-04-15 + 59日
           ≈ 2026-06-13

→ 報告：「現在の進度では、予定の 2026-05-31 ではなく
         2026-06-13 の完了となる見通し（+13日遅延）」
```

## 3. EVM データの収集・計算方法

### 月次データ収集プロセス

```
1. WBS から計画 PV を抽出
   - 各タスクの計画工数（時間 or コスト）
   - 計画完了日

2. 実績データを収集
   - 完了したタスク一覧（計画工数）
   - 実績工数（各タスクの実施時間）
   - 実績コスト（給与費、外注費等）

3. EV を計算
   - EV = Σ（完了したタスクの計画工数）

4. SPI, CPI を計算
   - SPI = EV / PV
   - CPI = EV / AC

5. トレンド分析
   - 前月との比較
   - EAC 再計算
   - 是正措置の効果測定
```

### Excel/Sheets テンプレート例

```
日付, PV(h), EV(h), AC(¥), SPI, CPI, EAC(¥), 評価
2026-03-31, 500, 450, 3,600,000, 0.90, 1.00, 8,000,000, △警告
2026-04-30, 1000, 800, 5,000,000, 0.80, 1.28, 6,250,000, ✗警告
2026-05-31, 1200, 1100, 6,500,000, 0.92, 1.23, 7,045,455, △改善傾向
```

## 5. EVM 傾向分析と早期警告

### 傾向分析の方法

```
直近3ヶ月の SPI 推移:
2月末: 1.02 (計画超過)
3月末: 0.90 (警告)
4月末: 0.80 (危機)

→ トレンド: SPI が悪化し続けている
   判定: 早期警告が必要、承認者報告推奨
```

### 早期警告の基準

```
以下のいずれかが発生した場合、即座に報告:

1. SPI < 0.9 が 3ヶ月連続
2. CPI < 0.95 が 3ヶ月連続
3. EAC が当初計画から 20% 以上超過
4. TCPI > 1.5 （残りの工程で非現実的な効率必要）
5. 予測完了日が納期を 2週間以上超える
```

### 自動エスカレーション フロー

```
SPI を日次監視
   ↓
[SPI < 0.85 を検出] → PM に通知 (翌日午前)
   ↓
[SPI < 0.9 が 3日連続] → 技術リード + PM で対応会議
   ↓
[SPI < 0.8] → ステアリングコミッティに報告（当日）
   ↓
是正措置の承認 + 実行
```

## 6. よくある誤用と対策

### 誤用 1: EV と実績工数の混同

```
❌ 間違い:
Task A (計画 40h) の実績が 45h なので、EV = 45h

✓ 正解:
Task A が完了したので、EV += 40h （計画値を使う）
```

### 誤用 2: 完了の定義曖昧

```
❌ 間違い:
「Task B は 80% 完了」 → 何%の EV を計上すべき？

✓ 正解:
「Task B は完全に完了」まで EV に計上しない
（0-100 ルール: タスクは完全に完了したときのみ100% の EV）
```

### 誤用 3: EAC を一度決めたら更新しない

```
❌ 間違い:
「4月初旬に EAC を ¥8,000,000 と計算したから、その値を使う」

✓ 正解:
毎月 EAC を再計算して、最新の状況を反映
（傾向変化を早期に検知するため）
```
