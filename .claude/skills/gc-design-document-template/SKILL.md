## 3. 実装方式・技術選定（Why/How）

### 3.1 ALB 選定理由

| 項目 | NLB | ALB | 選定 | 理由 |
|------|-----|-----|------|------|
| L7 ルーティング | ✗ | ✓ | ALB | パスベースルーティングが必要 |
| スループット | ✓✓ | ✓ | - | スループット要件は ALB で十分 |
| レイテンシ | <100μs | <400μs | - | ALB で十分 |
| コスト | 高 | 低 | ALB | コスト効率 |

選定: **ALB（Application Load Balancer）**

### 3.2 RDS Aurora 選定理由

MySQL 互換性、自動フェイルオーバー、Auto Scaling で可用性と性能を実現

### 詳細な章立てサンプル

```markdown
# セキュリティ設計書 v1.5

## 1. セキュリティ方針

### 1.1 セキュリティ目標

- 機密性: 認可されたユーザのみがアクセス可能
- 完全性: データの改ざんを検知・防止
- 可用性: セキュリティ対策がシステム停止につながらない

### 1.2 ISMAP 対応確認

✓ 以下の ISMAP 項目に対応:
- 認証 (ID/PW, MFA)
- 暗号化 (TLS 1.2以上)
- 監査ログ (CloudTrail)
- アクセス制御 (IAM)

---

## 2. 認証・認可設計（Who）

### 2.1 IAM ロール・ポリシー設計

#### EC2 インスタンスロール (ec2-app-role)

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "s3:GetObject"
      ],
      "Resource": "arn:aws:s3:::app-bucket/*"
    },
    {
      "Effect": "Allow",
      "Action": [
        "secretsmanager:GetSecretValue"
      ],
      "Resource": "arn:aws:secretsmanager:ap-ne-1:*:secret:app/*"
    }
  ]
}
```

**設計原則**: 最小権限（必要最小限のアクション）

### 2.2 MFA 要件

本番環境へのアクセス: MFA 必須（TOTP or U2F）

---

## 3. 暗号化戦略（What）

### 3.1 転送中データの暗号化

**TLS 1.2以上**を全通信に適用

| 通信 | 暗号化 | 強度 |
|------|--------|------|
| インターネット ↔ ALB | TLS 1.3 | ✓✓ 高 |
| ALB ↔ EC2 (VPC内) | TLS 1.2 | ✓ 中 |
| EC2 ↔ RDS (VPC内) | TLS 1.2 | ✓ 中 |
| S3 上のデータ | SSL/TLS | ✓ 中 |

### 3.2 保存中データの暗号化

**KMS マスターキー**で暗号化

| リソース | 暗号化方式 | キー管理 |
|----------|-----------|--------|
| RDS DB | KMS (AES-256) | AWS マネージド |
| EBS ボリューム | KMS (AES-256) | AWS マネージド |
| S3 バケット | KMS (AES-256) | AWS マネージド |

**KMS キーローテーション**: 自動（年1回）

---

## 4. ネットワークセキュリティ（What/How）

### 4.1 WAF ルール

CloudFront に統合

| ルール | 説明 |
|--------|------|
| SQLi | SQL Injection 検知・ブロック |
| XSS | Cross-Site Scripting 検知・ブロック |
| Rate Limiting | 1秒 100リクエスト超過をブロック |

### 4.2 DDoS 対策

AWS Shield Standard（自動）+ Standard Advanced（推奨）

---

## 5. 監査・コンプライアンス（How）

### 5.1 CloudTrail ロギング

**保存場所**: S3（ap-ne-1）
**保持期間**: 1年
**KMS 暗号化**: ✓ 有効

ロギング対象:
- IAM アクション（ユーザ/ロール作成等）
- EC2 操作（インスタンス起動停止等）
- RDS 操作
- S3 アクセス

### 5.2 Config コンプライアンスチェック

実施ルール:

| ルール | 説明 |
|--------|------|
| ec2-encrypted-volumes | 全 EBS は暗号化必須 |
| rds-encryption-enabled | RDS は暗号化必須 |
| s3-bucket-server-side-encryption-enabled | S3 は暗号化必須 |
| iam-policy-no-statements-with-admin-access | 管理者権限ポリシーを検知 |

---
