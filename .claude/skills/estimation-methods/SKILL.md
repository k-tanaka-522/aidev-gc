# 見積手法 ナレッジベース

## 概要
GC案件の工数見積に用いる4つの主要手法と、それぞれの計算ロジック・クロスチェック方法をまとめた実装ガイド。

---

## 手法1: FP（ファンクションポイント）法

### 概要
機能の規模（入力、出力、ファイル数など）から工数を推定。規模が定量的に測定しやすい案件向け。

### 計算式
```
未調整FP = Σ(機能ポイント)
調整FP = 未調整FP × 複雑度係数
工数 = 調整FP × 人日/FP（案件固有の経験値）
```

### GC案件での適用例

#### ステップ1: 機能ポイント計算

| 機能分類 | 複雑度 | 単位ポイント | 数 | 合計 |
|---------|-------|-----------|-----|------|
| **外部入力** | 低 | 3 | 5 | 15 |
| | 中 | 4 | 8 | 32 |
| | 高 | 6 | 2 | 12 |
| **外部出力** | 低 | 4 | 3 | 12 |
| | 中 | 5 | 5 | 25 |
| | 高 | 7 | 1 | 7 |
| **外部ファイル** | 低 | 5 | 2 | 10 |
| | 中 | 7 | 3 | 21 |
| | 高 | 10 | 1 | 10 |
| **内部ロジック** | 低 | 4 | 4 | 16 |
| | 中 | 5 | 6 | 30 |
| | 高 | 7 | 2 | 14 |
| **照合・参照ファイル** | 低 | 2 | 3 | 6 |
| | 中 | 3 | 5 | 15 |
| | 高 | 4 | 1 | 4 |
| **未調整FP合計** | - | - | - | **229** |

#### ステップ2: 複雑度係数適用

| 要因 | 度合い | ポイント |
|------|--------|---------|
| データ通信 | 中程度（LGWAN接続） | 2 |
| 分散処理 | あり（複数自治体） | 2 |
| パフォーマンス | 重視（RTO/RPO要件） | 2 |
| 並行処理 | 高い | 1 |
| セキュリティ | 高い（ISMAP対応） | 3 |
| 複雑度係数合計 | - | **10** |
| **複雑度係数（0.65 + 0.01×10）** | - | **0.75** |

```
調整FP = 229 × 0.75 = 171.75 FP
```

#### ステップ3: 工数変換

GC案件向けの経験値: **3.5人日/FP**（類似案件実績）

```
工数 = 171.75 × 3.5 = 601人日
```

### 適用シーン
- 機能が明確で、システムのインターフェース数が多い案件
- 新規構築案件（既存システムがない）

## 手法2: COCOMO（Constructive Cost Model）

### 概要
プロジェクト規模（KLOC: 千行コード）からボトムアップで工数を推定。開発工数が中心。

### 計算式
```
工数（人月） = a × (KLOC)^b
工数（人日）= 工数（人月）× 20営業日
```

### COCOMO パラメータ（基本モデル）

| プロジェクト分類 | a | b | 説明 |
|-------------|-----|-----|------|
| Organic | 2.4 | 1.05 | 小規模・経験者多い |
| Semi-detached | 3.0 | 1.12 | 中規模・混合要員 |
| Embedded | 3.6 | 1.20 | 大規模・組込み |

### GC案件での適用例

#### ステップ1: KLOC 推定

**対象:** 既存COBOL 50KLOC をJava に移行（R2移行）

```
既存コード: 50KLOC
移行率（コード削減と最適化）: 60%
新規コード KLOC = 50 × 0.6 = 30KLOC

実装対象の分類: Semi-detached（AWS ネイティブサービス利用あり）
```

#### ステップ2: 基本工数計算

```
工数（人月） = 3.0 × (30)^1.12
           = 3.0 × 37.9
           = 113.7 人月
工数（人日） = 113.7 × 20 = 2,274 人日
```

#### ステップ3: GC案件係数適用

| 調整要因 | 係数 | 理由 |
|--------|------|------|
| ISMAP セキュリティ対応 | 1.15 | ログ・監査追加 |
| IaC 開発（Terraform） | 1.10 | インフラコード追加 |
| テスト強化（セキュリティテスト） | 1.20 | 脆弱性診断など |
| 合計係数 | **1.51** | - |

```
調整工数 = 2,274 × 1.51 = 3,434 人日
```

### 適用シーン
- 言語変換（COBOL → Java など）を伴う R2 移行
- 既存コード規模がわかる案件

## 手法3: ボトムアップ法

### 概要
WBS の各タスクに標準工数を割り当て、合算する。最も直感的で使われやすい。

### ステップ

#### ステップ1: WBS タスク分解
gc-standard-wbs を参照し、対象フェーズのタスクを列挙。

例）Phase 2（要件定義）の場合：

| タスク | 標準工数 | 自治体規模係数 | セキュリティ係数 | 調整後工数 |
|--------|--------|-------------|-------------|---------|
| 2.1.1 ビジネス要件WS | 20人日 | 1.3 | 1.0 | 26人日 |
| 2.1.2 非機能要件WS | 20人日 | 1.0 | 1.5 | 30人日 |
| 2.1.3 IF要件WS | 15人日 | 1.0 | 1.0 | 15人日 |
| 2.2 現行調査 | 40人日 | 1.0 | 1.0 | 40人日 |
| 2.3 非機能詳細化 | 50人日 | 1.0 | 1.5 | 75人日 |
| 2.4 移行計画 | 30人日 | 1.3 | 1.0 | 39人日 |
| 2.5 要件定義書作成 | 50人日 | 1.0 | 1.0 | 50人日 |
| **小計** | **225人日** | - | - | **275人日** |

#### ステップ2: マージン・バッファ追加

```
見積工数 = 275人日
管理工数（PM、進捗管理）: +20%  = +55人日
リスク・予備費: +15%  = +41人日
合計: 275 + 55 + 41 = 371人日
```

### GC案件向け係数表

| 要因 | 係数 | 適用条件 |
|------|------|---------|
| 大規模自治体 | 1.3 | 調整・会議タスク |
| セキュリティレベル高 | 1.5 | セキュリティ・テストタスク |
| ネットワーク複雑度高 | 1.4 | ネットワーク設計タスク |
| ASP連携 | +8人日/システム | IF仕様、テスト |
| GCAS申請 | 40人日 固定 | Phase 0 |
| IaC化 | +1.2倍 | 構築フェーズ |

### 適用シーン
- 要件定義フェーズが完了した案件
- 詳細設計以降の見積（精度高い）
- テーラリング後の最終見積

## 手法4: 類推法

### 概要
過去の類似案件の実績から、調整係数を適用して推定。

### ステップ

#### ステップ1: 参考案件選択

**参考案件：** 中規模自治体、R1 移行、単独利用、セキュリティレベル中

| 項目 | 参考案件 | 対象案件 | 係数 |
|------|--------|--------|------|
| 自治体規模 | 中 | 大 | 1.3 |
| 移行方式 | R1 | R1 | 1.0 |
| GC利用方式 | 単独 | 共同 | 1.2 |
| セキュリティ | 中 | 高 | 1.5 |
| ネットワーク複雑度 | シンプル | 複雑 | 1.4 |
| 実績総工数 | **1,200人日** | - | - |

#### ステップ2: 調整係数計算

```
複合係数 = 1.3 × 1.2 × 1.5 × 1.4 = 3.276
推定工数 = 1,200 × 3.276 = 3,931人日
```

#### ステップ3: パラメータウェイト調整

完全な積算ではなく、影響度をウェイト付けする方法：

```
推定工数 = 基準工数 × Σ(ウェイト × 係数)

例）
- 自治体規模（ウェイト 20%）: 1.3 × 0.2 = 0.26
- 移行方式（ウェイト 25%）: 1.0 × 0.25 = 0.25
- セキュリティ（ウェイト 35%）: 1.5 × 0.35 = 0.525
- ネットワーク（ウェイト 20%）: 1.4 × 0.2 = 0.28
合計係数 = 1.0 + (0.26 + 0.25 + 0.525 + 0.28 - 1.0) = 1.315

推定工数 = 1,200 × 1.315 = 1,578人日
```

### 適用シーン
- 営業初期段階（概算見積）
- 類似の参考案件がある場合
- 詳細設計前のざっくり見積

## 手法5: 3 点見積（楽観/標準/悲観）

### 概要
タスク毎に 楽観値・標準値・悲観値 を見積もり、統計的に期待値を計算。

### 計算式

#### PERT（Program Evaluation and Review Technique）法

```
期待値 = (楽観値 + 4×標準値 + 悲観値) / 6
標準偏差 = (悲観値 - 楽観値) / 6
信頼区間 = 期待値 ± 1.96 × 標準偏差 (95% 信頼度)
```

### 適用例

#### Phase 2（要件定義）の見積

| タスク | 楽観値 | 標準値 | 悲観値 | 期待値 | 標準偏差 | 備考 |
|--------|-------|-------|-------|-------|---------|------|
| ビジネス要件WS | 15 | 20 | 30 | 20.8 | 2.5 | ユーザー協力的 |
| 非機能要件WS | 15 | 20 | 40 | 22.5 | 4.2 | 複雑度高い |
| IF要件WS | 10 | 15 | 25 | 15.8 | 2.5 | ASP少ない |
| 現行調査 | 30 | 40 | 60 | 41.7 | 5.0 | ドキュメント不足 |
| 非機能詳細化 | 40 | 50 | 70 | 51.7 | 5.0 | セキュリティ複雑 |
| 移行計画 | 25 | 30 | 45 | 31.7 | 3.3 | - |
| 要件定義書作成 | 35 | 50 | 70 | 51.7 | 5.8 | 複数回レビュー |

```
期待値合計 = 20.8 + 22.5 + 15.8 + 41.7 + 51.7 + 31.7 + 51.7 = 235.9人日
標準偏差合計 = √(2.5² + 4.2² + 2.5² + 5.0² + 5.0² + 3.3² + 5.8²) = 10.5人日

95% 信頼区間: 235.9 ± 1.96×10.5 = 235.9 ± 20.6 = [215.3, 256.5]
```

### シナリオ分析

```
楽観シナリオ（25% 確率）: 全タスクで楽観値を達成
  合計: 15+15+10+30+40+25+35 = 170人日

標準シナリオ（50% 確率）: 全タスクで標準値
  合計: 20+20+15+40+50+30+50 = 225人日

悲観シナリオ（25% 確率）: 全タスクで悲観値
  合計: 30+40+25+60+70+45+70 = 340人日

期待値 = 170×0.25 + 225×0.5 + 340×0.25 = 42.5 + 112.5 + 85 = 240人日
```

### 適用シーン
- リスク評価が必要な案件（不確実性が高い）
- ステアリングコミッティへの報告（信頼区間を示す）
- 複数フェーズの見積合算

## クロスチェック：4 手法の結果を比較

### 実例

**案件:** 中規模自治体、R1 移行、セキュリティレベル中

| 手法 | 見積工数 | 備考 |
|------|---------|------|
| **FP法** | 601人日 | 機能ポイント中心、全体スコープ |
| **COCOMO** | 3,434人日 | 開発工数が主、大規模 |
| **ボトムアップ** | 1,578人日 | タスク積算、精度高い |
| **類推法** | 1,578人日 | 参考案件ベース |
| **3点見積** | 1,450人日 | 期待値ベース |

### 乖離分析

```
ボトムアップ基準値: 1,578人日

乖離度:
- FP法: (601 - 1,578) / 1,578 = -61.9% （設計・テスト工数が過少）
- COCOMO: (3,434 - 1,578) / 1,578 = +117.6% （開発言語変換が多い場合）
- 類推法: (1,578 - 1,578) / 1,578 = 0% （最も整合）
- 3点見積: (1,450 - 1,578) / 1,578 = -8.1% （許容範囲内）
```

### クロスチェック判定ロジック

```
【判定結果】
- ボトムアップ ≈ 類推法 → OK（両者が整合）
- 3点見積期待値がボトムアップの±15% 以内 → OK
- FP法が乖離 → 「なぜか」を分析（設計・テスト工数の見落としなど）
- COCOMO が大きく乖離 → 「言語変換やインフラコード」の工数が別枠か確認
```

### 推奨見積値の決定

```
複数手法が整合した値を採用:
- ボトムアップ: 1,578人日 （ウェイト 40%）
- 類推法: 1,578人日 （ウェイト 30%）
- 3点見積: 1,450人日 （ウェイト 30%）

採用見積 = 1,578×0.4 + 1,578×0.3 + 1,450×0.3 = 1,530人日

最終見積（信頼区間）: 1,530人日 ±10% = [1,377, 1,683] 人日
```

## 見積精度の目安

| 見積フェーズ | 見積対象 | 精度 | 手法 |
|-----------|--------|------|------|
| **営業初期** | Phase 0-2 のみ | ±30% | FP法 / 類推法 |
| **要件定義後** | Phase 0-3（提案見積） | ±20% | ボトムアップ + 3点見積 |
| **詳細設計後** | Phase 0-8（全体） | ±10% | ボトムアップ + クロスチェック |
| **本稼働後** | 運用フェーズの月次工数 | ±5% | 実績ベース |
