# フェーズ × エージェント × スキル マトリクス

**目的**: 開発プロセスの各段階で、どのエージェントが何のスキルを使うかを明確化し、コンテキスト消費を最小化する

**参照元**:
- IPA共通フレーム2013（SLCP-JCF）
- `.claude/docs/10_facilitation/` フェーズガイド
- `docs/90_reseach/claude/IPAオーケストレーション設計書.xlsx.pdf` ★統合設計書

## 0. 統合設計書サマリ（2025-12-29追加）

### 解決する3課題

```
1. セッション跨ぎで情報が失われる → 状態の永続化設計（.claude-state/）
2. タスク漏れが起きる             → L4レベルまでタスク細分化
3. コンテキスト溢れ               → サブエージェントへの委譲設計
```

### 構成要素

| 要素 | 数 | 参照先 |
|------|-----|--------|
| L4タスク | 70件 | 統合設計書 Sheet2 |
| エージェント | 23件 | `.claude/agents/` |
| スキル | 48件 | `.claude/skills/INDEX.md` |

### IPA定義 vs 実務追加

```
IPA定義タスク:  約25件 (36%)
実務追加タスク: 約45件 (64%)  ← DevOps, 可観測性, FinOps等
```

## 1. 概要

### 1.1 4階層構造（IPA準拠）

```
Level 1: プロセス群         - テクニカル / マネジメント / 支援
Level 2: プロセス           - 企画 / 要件定義 / 設計 / 実装 / テスト / 運用
Level 3: アクティビティ     - フェーズ内の主要活動
Level 4: タスク（実務）     - 個別の作業単位 ★最小単位
```

### 1.2 フェーズ標準構造（5ステップ）

各フェーズは以下の標準構造に従う:

```
Step 1: インプット確認     - 前フェーズ成果物の読み込み
Step 2: 作業項目洗い出し   - 前フェーズから当フェーズの作業を展開 ★重要
Step 3: フェーズ実施       - 洗い出した作業を実行
Step 4: レビュー・承認     - 成果物の品質確認
Step 5: 次フェーズ引継ぎ   - 成果物の整理と引継ぎ
```

## 4. コンテキスト最適化

### 4.1 スキル階層化によるコンテキスト削減

```
従来: review-requirements を呼ぶ
→ 要件定義書全体 + 技術標準全体を読み込み（大量コンテキスト）

改善: review-performance-req を呼ぶ
→ 性能要件部分 + 技術標準(性能基準)のみ読み込み（最小コンテキスト）
```

### 4.2 各スキルのコンテキスト定義

| Level 3 スキル | 読み込むコンテキスト |
|--------------|-------------------|
| review-usecase | 要件定義書のユースケース部分のみ |

| review-security-req | セキュリティ要件 + 技術標準(セキュリティ基準) |
| review-class-design | クラス図 + 技術標準(言語規約) |
| review-api-design | API仕様書のみ |
