# サブエージェント定義

## 1. 概要

### 1.1 目的

各サブエージェントの役割、責務、参照・更新するリソースを定義する。

### 1.2 設計方針

```
1. 専門領域を明確に分離
2. 成果物の責任を明確化
3. 状態更新ルールを統一
```

---

## 2. サブエージェント一覧

| Agent | 役割 | 専門領域 |
|-------|------|---------|
| Consultant | 企画・要件引出 | ビジネス分析、要件定義 |
| App-Architect | アプリ設計・技術判断 | アーキテクチャ、API、DB設計 |
| Infra-Architect | インフラ設計 | AWS構成、ネットワーク、セキュリティ |
| Coder | 実装 | コーディング、単体テスト |
| QA | テスト・品質 | テスト設計、E2E、品質保証 |
| SRE | インフラ・運用 | IaC、CI/CD、監視 |

### 3.4 Coder

| 項目 | 内容 |
|------|------|
| **役割** | 実装（**TDD 必須**） |
| **やること** | **TDD サイクル**（RED→GREEN→REFACTOR→COMMIT）、リファクタリング |
| **参照するもの** | `40_standards/`、`skills/languages/`、`skills/process/`、**実装計画書** |
| **更新するもの** | `tasks.json`、`src/`、`tests/unit/` |

**重要ルール**:
- **TDD 必須**: テストを書く前に本番コードを書いたら、そのコードは削除

- **入力**: 実装計画書のタスク1つ（設計書全体ではない）

## 4. 共通ルール

### 4.1 状態更新ルール

**全サブエージェント共通**：作業完了時に以下を必ず実行する。

#### 1. tasks.json を更新

```json
{
  "task-id": {
    "status": "done",
    "output": "成果物のパス",
    "completedAt": "2025-01-15T10:00:00Z",
    "agent": "Coder"
  }
}
```

#### 2. decisions.json に重要な決定を記録

技術的な判断を行った場合：

```json
{
  "decision-id": {
    "decision": "何を決めたか",
    "reason": "なぜそう決めたか",
    "alternatives": ["検討した代替案1", "検討した代替案2"],
    "decidedAt": "2025-01-15",
    "decidedBy": "Architect"
  }
}
```

#### 3. PMに結果を報告

- 成果物のパス
- 完了したこと
- 次に必要なこと（あれば）

### 4.2 PMとの関係

```
PM → サブエージェント: タスク委譲
サブエージェント → PM: 結果報告
```

- PMから委譲されたタスクを実行
- ユーザーとは直接対話しない（すべてPM経由）
- 完了したらPMに報告

## 6. スキルとの関係

### 6.1 エージェント×スキル対応

| Agent | 使用するスキルカテゴリ |
|-------|---------------------|
| Consultant | - |
| App-Architect | architecture/, api/, **process/** |
| Infra-Architect | architecture/ |
| Coder | languages/, **process/** |
| QA | testing/ |
| SRE | devops/, observability/ |

### 6.2 スキルのロードタイミング

```
1. PM: プロジェクトの技術スタックを確認
2. PM: activeSkills を設定
3. PM: サブエージェントに委譲時、必要なスキルを指定
4. サブエージェント: 指定されたスキルを参照して作業
```

## 7. Fresh Context（コンテキスト汚染防止）

### 7.1 問題

PMやサブエージェントが長い会話を続けると、コンテキストが断片化して品質が低下する。

### 7.2 解決策

**タスクごとに新規サブエージェントを起動**

```
PM（軽量オーケストレーター）
  │
  ├─ Task 1 → fresh Coder → 完了 → 破棄
  │              ↓
  │         状態は .claude-state/ に永続化
  │
  ├─ Task 2 → fresh Coder → 完了 → 破棄
  │
  └─ Task N → ...
```

### 7.3 ルール

**PM の責務**:
1. 委譲前に `.claude-state/` に状態を記録
2. タスクに必要な情報を**全文**で渡す（ファイルパスだけでなく内容も）
3. 同じサブエージェントを使い回さない
4. サブエージェントからの結果を `.claude-state/` に記録

**禁止**:
- 同じ Coder に複数タスクを連続で渡す
- 「前のタスクの続き」という曖昧な指示
- ファイルパスだけ渡して「読んで」という指示

### 7.4 詳細

詳細は `.claude/helpers/fresh-context-guide.md` を参照。
