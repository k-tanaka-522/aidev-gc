# aidev アップグレード設計書 v4 - 概要

## 1. 背景

### 1.1 aidevとは

aidevは、Claude Codeを活用したAI駆動開発ファシリテーターである。PM（プロジェクトマネージャー）を中心に、専門領域を持つサブエージェント（Consultant, Architect, Coder, QA, SRE）が協調して、ソフトウェア開発プロジェクトを推進する。

### 1.2 現状の課題

運用を通じて、以下の課題が顕在化した：

| # | 課題 | 症状 | 影響 |
|---|------|------|------|
| 1 | **セッション切れで情報が失われる** | 新しいセッションで「前回何をしたか」がわからない | 同じ説明を繰り返す、作業の重複 |
| 2 | **PMが役割を逸脱する** | PMが自分でコードや設計書を書いてしまう | サブエージェントの専門性が活かされない |
| 3 | **コンテキストが溢れる** | 大量のドキュメントを読み込んで処理が重くなる | レスポンス低下、情報の取りこぼし |
| 4 | **既存プロジェクトに導入しにくい** | 新規プロジェクト前提の設計 | 途中からの導入が困難 |

---

## 2. 目的

本設計書は、上記課題を解決し、aidevをより実用的なツールへアップグレードすることを目的とする。

### 2.1 ゴール

1. **セッション永続性**: セッションが切れても、前回の続きから作業を再開できる
2. **役割の明確化**: PMはファシリテーションに徹し、成果物作成はサブエージェントが担う
3. **効率的なコンテキスト管理**: 必要な情報だけを必要な時にロードする
4. **既存プロジェクト対応**: 既にコードやドキュメントがあるプロジェクトにも導入できる

### 2.2 非ゴール

- 全タスクの事前定義（AIが状況に応じて判断する）
- 厳密なフェーズゲート（柔軟なフェーズ移行を許容する）
- 完全自動化（ユーザー承認を必要なポイントで求める）

---

## 3. 設計方針

### 3.1 基本原則

```
定義するのは「仕組み」だけ
詳細な判断はAIに任せる
```

| 定義するもの | 定義しないもの |
|-------------|---------------|
| 状態管理の構造 | 個別タスクの詳細 |
| 役割分担 | ヒアリング内容 |
| ファイル構成 | 品質判断の基準値 |
| コマンドフロー | 例外対応の詳細 |

### 3.2 設計判断

| 判断ポイント | 選択 | 理由 |
|-------------|------|------|
| 状態の保存形式 | JSON + Markdown | 機械可読性と人間可読性の両立 |
| PMの責務範囲 | ファシリテーション特化 | コンテキスト肥大化防止、専門性の活用 |
| スキルの管理 | オンデマンドロード | コンテキスト効率化 |
| フェーズ定義 | 大枠のみ | AIの柔軟な判断を許容 |

## 4. アーキテクチャ

### 4.1 全体構成

```
┌─────────────────────────────────────────────────────────┐
│                      ユーザー                            │
└───────────────────────┬─────────────────────────────────┘
                        │ /init, /status, /next
                        ▼
┌─────────────────────────────────────────────────────────┐
│                   PM（軽量）                             │
│                                                         │
│  【やること】           【やらないこと】                   │
│  ・ユーザー対話         ・コードを書く → Coder            │
│  ・ファシリテーション   ・設計書を書く → Architect        │
│  ・ルーティング         ・技術判断 → Architect           │
│  ・進捗報告             ・品質判断 → QA                  │
└───────────────────────┬─────────────────────────────────┘
                        │
        ┌───────────────┼───────────────┬───────────────┐
        ▼               ▼               ▼               ▼
   Consultant      Architect         Coder           SRE
   企画・要件      設計・技術判断    実装            インフラ
        │               │               │               │
        └───────┬───────┴───────┬───────┴───────┬───────┘
                │               │               │
            + Skills        + Skills        + Skills
                │               │               │
                └───────────────┴───────────────┘
                                │
                                ▼
                    ┌─────────────────────┐
                    │      状態管理        │
                    │  ・project-state    │
                    │  ・tasks            │
                    │  ・decisions        │
                    │  ・context          │
                    └─────────────────────┘
```

### 4.2 レイヤー構成

| Layer | 役割 | 担当 |
|-------|------|------|
| Layer 1 | オーケストレーション | PM |
| Layer 2 | 専門作業 | サブエージェント + スキル |
| Layer 3 | 永続化 | 状態ファイル（.claude-state/） |
