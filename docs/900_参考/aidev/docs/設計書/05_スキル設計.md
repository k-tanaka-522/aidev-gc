# スキル設計

## 1. 概要

### 1.1 スキルとは

```
スキル = 必要な時だけロードする専門知識
```

サブエージェントが特定のタスクを実行する際に参照する、専門領域の知識・ベストプラクティス集。

### 1.2 なぜスキルが必要か

| 問題 | 原因 | 解決策 |
|------|------|--------|
| コンテキストが溢れる | 全知識を常時ロード | 必要時だけロード |
| 知識の更新が困難 | 散在した情報 | スキルとして整理 |
| 新技術への対応が遅い | 固定的な構成 | スキル追加で対応 |

### 1.3 設計方針

```
1. オンデマンドロード（必要な時だけ）
2. カテゴリで整理（検索しやすく）
3. 拡張可能（新しいスキルを追加できる）
```

## 2. スキルの構造

### 2.1 ディレクトリ構成

```
.claude/skills/
├── CATALOG.md              # スキル一覧（検索用インデックス）
│
├── meta/                   # メタスキル
│   └── skill-creator/      # 新規スキル作成用
│
├── process/                # プロセススキル【新規】
│   ├── writing-plans/      # 実装計画書作成
│   └── test-driven-dev/    # TDD（テスト駆動開発）
│
├── languages/              # 言語スキル
│   ├── typescript/
│   ├── python/
│   └── go/
│
├── architecture/           # アーキテクチャスキル
│   ├── c4-modeling/
│   ├── adr/
│   └── ddd/
│
├── api/                    # APIスキル
│   └── openapi/
│
├── devops/                 # DevOpsスキル
│   ├── cicd/
│   ├── cloudformation/
│   └── terraform/
│
├── testing/                # テストスキル
│   ├── e2e/
│   └── load/
│
└── observability/          # 可観測性スキル
    ├── logging/
    └── metrics/
```

### 2.2 スキルの内部構成

各スキルは以下の構造を持つ：

```
{category}/{skill}/
├── SKILL.md               # スキルの知識・手法（必須）
└── templates/             # 関連テンプレート（オプション）
```

### 2.3 SKILL.md の構成

```markdown
# {スキル名}

## 概要
このスキルの目的と適用場面

## 使用方法
具体的な使い方、コマンド、ツール

## ベストプラクティス
推奨される使い方、注意点

## 例
具体的なコード例、設定例

## 参考資料
公式ドキュメントへのリンク
```

## 3. スキルカタログ (CATALOG.md)

### 3.1 目的

PMが `/init` 時にプロジェクトの技術スタックを確認し、必要なスキルを特定するためのインデックス。

### 3.2 構成

```markdown
# スキルカタログ

## 検索方法
技術スタック → 該当スキルを検索

## スキル一覧

| カテゴリ | スキルID | 用途 | 使用Agent |
|---------|---------|------|----------|
| meta | skill-creator | 新規スキル作成 | Coder |
| **process** | **writing-plans** | **実装計画書作成** | **App-Architect** |
| **process** | **test-driven-dev** | **TDD（テスト駆動開発）** | **Coder** |
| languages | typescript | TypeScript実装 | Coder |
| languages | python | Python実装 | Coder |
| languages | go | Go実装 | Coder |
| architecture | c4-modeling | C4アーキテクチャ図 | Architect |
| architecture | adr | 設計決定記録 | Architect |
| architecture | ddd | ドメイン駆動設計 | Architect |
| api | openapi | OpenAPI仕様 | Architect |
| devops | cicd | CI/CDパイプライン | SRE |
| devops | cloudformation | AWS CFn | SRE |
| devops | terraform | Terraform | SRE |
| testing | e2e | E2Eテスト | QA |
| testing | load | 負荷テスト | QA |
| observability | logging | 構造化ログ | SRE |
| observability | metrics | メトリクス設計 | SRE |
```

## 4. スキル選択の仕組み

### 4.1 フロー

```
1. /init 時
   └─ PM: 技術スタックを確認（ヒアリング or 分析）
       ↓
2. スキル特定
   └─ PM: CATALOG.md から該当スキルを検索
       ↓
3. activeSkills 設定
   └─ PM: project-state.json に記録
       ↓
4. 作業時
   └─ PM: サブエージェントに委譲時、必要なスキルを指定
       ↓
5. スキル参照
   └─ サブエージェント: 指定されたスキルを読み込んで作業
```

### 4.2 project-state.json での管理

```json
{
  "name": "ECサイト構築",
  "techStack": {
    "frontend": "TypeScript, React",
    "backend": "TypeScript, NestJS",
    "database": "PostgreSQL",
    "infra": "AWS"
  },
  "activeSkills": [
    "typescript",
    "react",
    "nestjs",
    "openapi",
    "cloudformation"
  ]
}
```

## 5. 新しいスキルの追加

### 5.1 いつ追加するか

1. CATALOG.md に該当スキルがない
2. 新しい技術・フレームワークを使用する
3. 既存スキルでは不十分

### 5.2 追加フロー

```
1. PM: 必要なスキルがないことを検知
    ↓
2. PM: Coder + skill-creator に委譲
    ↓
3. Coder: 新規スキルを作成
   - SKILL.md を作成
   - 必要ならテンプレートも作成
    ↓
4. Coder: CATALOG.md に追加
    ↓
5. PM: activeSkills に追加
```

### 5.3 skill-creator の役割

`meta/skill-creator/SKILL.md` には、新しいスキルを作成するためのガイドラインが含まれる：

- スキルの構成テンプレート
- 命名規則
- 品質基準

## 6. 初期スキル

### 6.1 優先度順

| 優先度 | スキル | 理由 |
|--------|--------|------|
| 1 | skill-creator | スキル追加の基盤 |
| **2** | **writing-plans** | **実装計画の標準化（Phase 2.5）** |
| **3** | **test-driven-dev** | **TDD 必須化（品質向上）** |
| 4 | typescript | 最も使用頻度が高い |
| 5 | python | 次に使用頻度が高い |
| 6 | c4-modeling | 設計の基本 |
| 7 | adr | 決定記録の標準化 |

### 6.2 後から追加

以下は必要に応じて追加：

- go, rust, java（言語）
- ddd, clean-architecture（アーキテクチャ）
- openapi（API）
- cicd, cloudformation, terraform（DevOps）
- e2e, load（テスト）
- logging, metrics, tracing（可観測性）

## 7. コンテキスト管理

### 7.1 ロードタイミング

| タイミング | ロードするもの |
|-----------|--------------|
| /init 時 | CATALOG.md のみ |
| 作業委譲時 | 必要なスキルのみ |

### 7.2 ロードしないもの

- 使用しないスキル
- 関係のないカテゴリ

### 7.3 効果

```
Before: 全スキル常時ロード → コンテキスト肥大化
After:  必要なスキルだけ → コンテキスト最適化
```
