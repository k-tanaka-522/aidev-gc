# コマンドフロー

## 1. 概要

### 1.1 ユーザーが使うコマンド

| コマンド | 目的 | 使用タイミング |
|---------|------|---------------|
| `/init` | プロジェクト開始/再開 | セッション開始時 |
| `/status` | 現在の状況確認 | 進捗確認時 |
| `/next` | 次のアクションを進める | 作業を進める時 |

### 1.2 設計方針

```
1. 状態ベース: .claude-state/ を常に参照
2. 冪等性: 何度実行しても同じ結果
3. 透明性: 何をしているか明示
```

---

## 2. /init フロー

### 2.1 目的

プロジェクトを開始、または前回の続きから再開する。

### 2.2 フロー図

```
ユーザー: /init
    │
    ▼
PM: .claude-state/ 確認
    │
    ├─ 存在する（継続プロジェクト）
    │   │
    │   ▼
    │  状態ファイル読み込み
    │  - project-state.json
    │  - tasks.json
    │  - decisions.json
    │  - context.md
    │   │
    │   ▼
    │  PM: 「前回の続きですね。
    │       現在: {phase}
    │       次: {context.mdから}
    │       /next で進めましょう」
    │
    └─ 存在しない
        │
        ▼
       既存資産の確認
       (src/, docs/, tests/, infra/)
        │
        ├─ 既存資産あり（既存プロジェクト）
        │   │
        │   ▼
        │  PM: 「既存プロジェクトですね」
        │   │
        │   ▼
        │  サブエージェントに分析委譲
        │  - Architect: 設計書分析
        │  - Coder: コード分析
        │  - QA: テスト分析
        │   │
        │   ▼
        │  分析結果を統合・報告
        │   │
        │   ▼
        │  .claude-state/ 初期化
        │
        └─ 既存資産なし（新規プロジェクト）
            │
            ▼
           .claude-state/ 初期化
            │
            ▼
           PM: 「何を作りたいですか？」
```

### 2.3 詳細処理

#### 継続プロジェクトの場合

1. **状態読み込み**
   ```
   Read: .claude-state/project-state.json
   Read: .claude-state/tasks.json
   Read: .claude-state/decisions.json
   Read: .claude-state/context.md
   ```

2. **状況報告**
   ```
   📂 前回の続きです

   プロジェクト名: {name}
   現在のフェーズ: {phase}
   次にやること: {context.mdから抽出}

   /next で進めましょう
   ```

#### 既存プロジェクトの場合

1. **分析委譲**
   - Architect: 設計書・アーキテクチャ分析
   - Coder: コード分析（言語、フレームワーク、構成）
   - QA: テストカバレッジ分析

2. **結果報告**
   ```
   📂 既存プロジェクトを分析しました

   現在の状況:
   - 設計書: {有無と内容}
   - コード: {言語、フレームワーク、進捗}
   - テスト: {種類、カバレッジ}

   推奨:
   1. {最優先で必要なこと}
   2. {次に必要なこと}

   どこから始めますか？
   ```

#### 新規プロジェクトの場合

1. **初期化**
   ```
   Create: .claude-state/project-state.json
   Create: .claude-state/tasks.json
   Create: .claude-state/decisions.json
   Create: .claude-state/context.md
   ```

2. **報告**
   ```
   🆕 新規プロジェクトを初期化しました

   何を作りたいですか？
   ```

## 3. /status フロー

### 3.1 目的

現在のプロジェクト状況を確認する。

### 3.2 フロー図

```
ユーザー: /status
    │
    ▼
PM: 状態ファイル読み込み
    │
    ▼
PM: 状況報告
    │
    ▼
出力:
┌────────────────────────────────────┐
│ 📊 プロジェクト状況                 │
│                                    │
│ プロジェクト: {name}               │
│ フェーズ: {phase}                  │
│                                    │
│ ■ 完了タスク                       │
│ - {done tasks}                     │
│                                    │
│ ■ 進行中タスク                     │
│ - {in-progress tasks}              │
│                                    │
│ ■ 未着手タスク                     │
│ - {pending tasks}                  │
│                                    │
│ ■ 重要な決定事項                   │
│ - {decisions}                      │
└────────────────────────────────────┘
```

## 4. /next フロー

### 4.1 目的

次のアクションを特定し、実行する。

### 4.2 フロー図

```
ユーザー: /next
    │
    ▼
PM: tasks.json 確認 → 次タスク特定
    │
    ▼
PM: 次のアクション提案
    │
    ▼
ユーザー: 承認 or 修正指示
    │
    ▼
PM: サブエージェントに委譲
    │ （例: Architect + c4-modeling スキル）
    │
    ▼
サブエージェント: 作業実行
    │
    ▼
サブエージェント: tasks.json 更新
    │ - status: "done" or "review"
    │ - output: ファイルパス
    │ - completedAt: 日時
    │
    ▼
サブエージェント: PM に報告
    │
    ▼
PM: ユーザーに結果報告
```

### 4.3 タスク特定ロジック

```
1. status: "in-progress" のタスクがあれば → それを継続
2. なければ status: "pending" の最初のタスク → それを開始
3. 全て "done" なら → フェーズ移行を提案
```

### 4.4 出力例

```
🎯 次にやるべきこと

C4モデル（コンテナ図）を作成する

理由：設計フェーズを完了するために必要な項目で、
　　　API設計の前提となります。

進めますか？
```

## 5. 修正フロー

### 5.1 目的

ユーザーからの修正依頼に対応する。

### 5.2 フロー図

```
ユーザー: 「ここ修正して」
    │
    ▼
PM: tasks.json の status を "revision" に
    │
    ▼
PM: 同じサブエージェントに修正依頼
    │ （フィードバック内容を伝える）
    │
    ▼
サブエージェント: 修正実行
    │
    ▼
サブエージェント: tasks.json 更新
    │ - status: "review"
    │
    ▼
PM: ユーザーに再確認
```

### 5.3 状態遷移

```
done/review → revision → review → done
```

## 6. 状態更新ルール

### 6.1 tasks.json の更新

タスク完了時、サブエージェントは必ず以下を更新：

```json
{
  "task-id": {
    "status": "done",
    "output": "docs/03_設計/api-design.md",
    "completedAt": "2025-01-15T10:00:00Z",
    "agent": "Architect"
  }
}
```

### 6.2 decisions.json の更新

重要な決定があった場合：

```json
{
  "decision-id": {
    "decision": "何を決めたか",
    "reason": "なぜそう決めたか",
    "alternatives": ["検討した代替案"],
    "decidedAt": "2025-01-15",
    "decidedBy": "Architect"
  }
}
```

### 6.3 context.md の更新

セッション終了時、PMが更新：

```markdown
## 現在の状況

**最終更新**: 2025-01-15
**現在フェーズ**: 設計

### 直前の作業内容

- API設計書を作成
- 認証方式をJWTに決定

### 次にやるべきこと

1. C4モデルの作成
2. DB設計
```
