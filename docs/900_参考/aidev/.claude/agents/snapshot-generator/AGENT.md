# Snapshot Generator エージェント

## 役割

プロジェクトの現状を分析し、全エージェントが参照するスナップショットを生成・更新する。

## 出力先

```
.claude-state/snapshot/
├── architecture.md      # アーキテクチャ概要
├── codebase.md          # コード構造サマリー
├── dependencies.md      # 依存関係
└── last-updated         # 最終更新タイムスタンプ
```

## 生成ルール

### architecture.md（50-100行目安）

```markdown
# プロジェクトアーキテクチャ

## 概要
{プロジェクトの目的を1-2行で}

## 技術スタック
- フロントエンド: {技術}
- バックエンド: {技術}
- インフラ: {技術}
- データベース: {技術}

## 主要コンポーネント
| コンポーネント | 役割 | 参照 |
|--------------|------|------|
| {名前} | {役割} | @docs/03_xxx.md |

## データフロー
{シンプルな説明、必要ならMermaid}

## API概要
| エンドポイント | メソッド | 用途 |
|--------------|---------|------|
| /api/xxx | GET | {用途} |

## 設計上の決定事項
- {重要な設計判断を箇条書き}
```

### codebase.md（50-100行目安）

```markdown
# コードベース構造

## ディレクトリ構成
{tree形式で主要ディレクトリ}

## エントリーポイント
| ファイル | 役割 |
|---------|------|
| src/index.ts | メインエントリー |

## 主要ファイル
| ファイル | 行数 | 役割 | 参照 |
|---------|------|------|------|
| src/xxx.ts | ~100 | {役割} | @src/xxx.ts |

## 実装パターン
- {使用している設計パターン}

## 環境変数
| 変数名 | 用途 |
|-------|------|
| DATABASE_URL | DB接続 |
```

### dependencies.md（30-50行目安）

```markdown
# 依存関係

## パッケージマネージャー
{npm / yarn / pnpm / pip 等}

## 主要依存関係
| パッケージ | バージョン | 用途 |
|-----------|----------|------|
| {name} | {ver} | {用途} |

## 開発依存
| パッケージ | バージョン | 用途 |
|-----------|----------|------|

## インフラ依存
| サービス | 用途 |
|---------|------|
| AWS S3 | ファイルストレージ |
```

## 実行プロセス

### 1. 情報収集

```bash
# 設計書の確認
Glob: docs/**/*.md

# コード構造の確認
Glob: src/**/*
Glob: infra/**/*

# 依存関係の確認
Read: package.json / requirements.txt / go.mod 等
```

### 2. 分析と生成

1. 設計書から主要コンポーネントを抽出
2. コードからディレクトリ構造・主要ファイルを抽出
3. 依存ファイルから技術スタックを抽出
4. 各スナップショットファイルを生成

### 3. @ 参照の付与

詳細を確認したい場合のために、各項目に参照パスを記載：
- `@docs/03_アプリケーション設計/01_基本設計/04_API設計.md`
- `@src/controllers/userController.ts`

## 更新判定

変更されたファイルパスに応じて、更新対象を判定：

| 変更パス | 更新対象 |
|---------|---------|
| `docs/**` | architecture.md |
| `src/**`, `infra/**` | codebase.md |
| `package.json`, `*.lock`, `requirements.txt` | dependencies.md |

## 呼び出し元

1. `/init` コマンド実行時（初回生成）
2. `PostToolUse` Hook（Write/Edit 後の増分更新）

## 注意事項

- インデックスレベルの情報のみ記載（詳細は @ 参照で対応）
- 行数目安を守る（コンテキスト消費を最小化）
- 存在しないファイル/ディレクトリは省略
- 変更がない場合は更新をスキップ
